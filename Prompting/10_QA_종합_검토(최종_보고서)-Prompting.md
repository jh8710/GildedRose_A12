# Gilded Rose QA 최종 보고서

## 1. Executive Summary

Gilded Rose Java 프로젝트의 QA 활동은 요구사항 분석, 코드 품질 분석, 테스트 계획, 테스트 케이스 작성, 테스트 실행·결함 분석, Golden Master 자동화, 리팩토링 지원, 결함 관리 체계 수립까지 9단계로 진행되었다.

최종 검증 기준으로 `mvn test`를 실행한 결과, 단위 테스트 34개와 Golden Master 테스트 1개가 모두 통과했다.

| 항목 | 결과 | 판정 |
| --- | --- | --- |
| 자동화 테스트 | 35개 실행 / 35개 통과 | Pass |
| 테스트 통과율 | 100% | 목표 달성 |
| 요구사항 시나리오 커버 | 주요 시나리오 27개 기준 테스트 연결 | 목표 달성 |
| ItemType 커버 | Normal, Aged Brie, Backstage Pass, Sulfuras, Conjured 5종 | 목표 달성 |
| JaCoCo 라인 커버리지 | 미측정 (`jacoco-maven-plugin` 미설정) | 개선 필요 |
| JaCoCo 브랜치 커버리지 | 미측정 (`jacoco-maven-plugin` 미설정) | 개선 필요 |
| Open Critical/Major 결함 | 0건 | Pass |

현재 기능 검증 관점에서는 Green 상태이나, 커버리지 게이트는 아직 자동화되지 않았다. 다음 단계에서는 JaCoCo를 `pom.xml`에 추가해 라인/브랜치 커버리지 90% 이상을 CI 게이트로 고정하는 것이 우선이다.

## 4. 9단계 QA 활동 평가

| 단계 | 활동 | 효과 | 평가 |
| --- | --- | --- | --- |
| 1 | CursorRules 설계 | `Item` 클래스 수정 금지, 테스트 Green 후 리팩토링 원칙 고정 | 효과적 |
| 2 | 요구사항 분석 | 5개 ItemType과 27개 주요 시나리오 도출 | 매우 효과적 |
| 3 | 코드 품질 분석 | SRP/OCP 위반, Magic Number, 중복 로직 등 리팩토링 포인트 식별 | 효과적 |
| 4 | 테스트 계획 | P0/P1/P2 우선순위와 경계값 매트릭스 수립 | 매우 효과적 |
| 5 | 테스트 케이스 작성 | 34개 파라미터화 단위 테스트로 핵심 규칙 보호 | 매우 효과적 |
| 6 | 테스트 실행·결함 분석 | `mvn test` Green 및 결함 없음 확인 | 효과적 |
| 7 | Golden Master 자동화 | 30일 출력 기반 회귀 안전망 확보 | 매우 효과적 |
| 8 | 리팩토링 지원 | 안전한 구조 개선 로드맵 제공 | 효과적이나 일부 실행 필요 |
| 9 | 결함 관리 체계 | Severity × ItemType 분류와 보고 템플릿 수립 | 효과적이나 운영 자동화 필요 |

### 4.1 가장 효과적이었던 단계

1. 요구사항 분석
2. 테스트 계획 및 테스트 케이스 작성
3. Golden Master 자동화
4. 결함 관리 체계

### 4.2 개선이 필요한 단계

1. 커버리지 측정(JaCoCo)
2. CI 자동화
3. 결함 워크플로우 운영
4. 리팩토링 실행(OCP 잔여 부채)

## 5. 다음 레거시 프로젝트를 위한 Best Practice 5가지

1. 요구사항을 먼저 테스트 가능한 규칙으로 쪼갠다.
2. P0/P1/P2 우선순위를 두고 작은 테스트 안전망부터 만든다.
3. Golden Master를 단위 테스트의 보완재로 사용한다.
4. 커버리지 숫자보다 요구사항 매핑을 먼저 확보하고, 이후 JaCoCo로 게이트화한다.
5. 결함 분류는 도메인 축과 심각도 축을 함께 사용한다.

## 8. 최종 결론

이번 QA 활동은 레거시 Gilded Rose 프로젝트를 요구사항 기반으로 재정렬하고, 핵심 도메인 규칙을 테스트로 보호하며, 결함 관리와 리팩토링 기준까지 수립했다는 점에서 성공적이다.

현재 기준으로 자동화 테스트는 35개 모두 통과하며, Open Critical/Major 결함은 없다. 다만 JaCoCo 기반 커버리지 수치가 아직 없으므로, “기능 테스트 Green” 상태와 “커버리지 게이트 완료” 상태를 구분해야 한다.

다음 단계의 핵심은 **JaCoCo + CI + Issue Workflow**를 연결해 현재의 QA 산출물을 운영 가능한 품질 게이트로 전환하는 것이다.
